# The role system for Claude Code

A role is a standing set of instructions that tells the AI how to approach and solve work in
a given project. It plays the part of a system prompt: guidance that is in force for the
whole session and shapes every answer, such as "ask before changing files", "stop after two
failed debugging attempts", or "write in neutral third person".

Technically it is not the system prompt itself. Claude Code has its own built-in system
prompt, which the role system does not touch. The role arrives as context that a
`SessionStart` hook injects at the start of the session, alongside the global `CLAUDE.md`.
For the AI's behavior the effect is much the same.

## Where it lives

The files are in the `nixos-config` repository, under `devenv/claude/`. At the time of
writing the repository is private, so the links need access to the owning account.

## How it works

1. **Choosing a role.** A project's `CLAUDE.md` declares a role with a line such as
   `## ACTIVE ROLE:  WIKI-AUTHOR`. At session start, `session-start.sh` resolves the role in
   this order:
   1. the `$CLAUDE_ROLE` environment variable
   2. the nearest `CLAUDE.md` containing an `ACTIVE ROLE:` line, searching from the current
      folder up to the git root
   3. the default, `DEV`
2. **Inheritance.** Each role file in `~/.claude/LLM/roles/` begins with `EXTENDS: <parent>`.
   `generate-preamble.js` follows the chain up to `COMMON`. For a wiki-writing project the
   chain is:

   ```text
   WIKI-AUTHOR  →  WRITER  →  COMMON
   ```

   `WRITER` is a shared base for `WIKI-AUTHOR` and `BLOG-AUTHOR`, so writing habits live in
   one file.
3. **What gets loaded.** The script does not paste the role files into the session. It
   builds a table with one row per `##` section: the directive name, the file it came from,
   and a summary of at most 160 characters taken from the section's bolded rule. A wiki
   session gets 16 rows, where the role files hold more than 300 lines (326 at last count).
   The table is injected as the session preamble, and the assistant opens its first reply
   with it.
4. **One authority.** The global `CLAUDE.md` forbids the assistant from reading the role
   files or working out the role itself. If the configuration is broken (a missing file, a
   missing `EXTENDS`, or a cycle), the script exits with code 2 and a
   `CLAUDE ROLE CONFIG ERROR`. The failure surfaces instead of being worked around.

## Benefits

- **Relevance.** A TypeScript session does not carry wiki-writing rules, and a wiki session
  does not carry debugging protocols. The design notes argue that extra instructions dilute
  attention. Their stronger argument is the "lost in the middle" result (Liu et al., 2023),
  which found that models follow instructions in the middle of a long context less reliably.
  The notes call the softmax-dilution argument real but only partial.
- **Growth.** The notes expect the rule corpus to triple. Only the rows for the active chain
  are ever loaded.
- **Reuse.** Shared habits sit once, in `COMMON` or `WRITER`, and every role inherits them.
- **Same behavior in Docker and on the host.** The script is Node, so it runs unchanged in
  both.

## The caching aspect

Anthropic's prompt cache is keyed on the exact bytes at the start (the prefix) of a request.
Two requests share a cache entry only if everything before the point where they differ is
identical. The design uses this in three ways:

- **Root first, leaf last.** The table lists the `COMMON` rows first, then the parent rows,
  then the leaf. Sessions with different roles start with the same block, giving them the
  longest possible shared prefix. A `DEV` session and a `WIKI-AUTHOR` session share the
  `COMMON` rows. If the leaf came first, no two roles would share anything.
- **Byte-identical output.** The script is deterministic: the same role gives the same table,
  with no timestamps or random content. Repeated sessions on one role can reuse the cache
  entry while it has not expired.
- **Volatile text kept out.** `DECISIONS.md` §20 records a defect fixed on 2026-08-23. The
  script used to prepend `git status` output for `devenv/` to the injected text. Every
  distinct working-tree state produced a distinct prefix, so sessions almost never shared a
  cache entry. That warning now goes through the hook's `systemMessage` field, which appears
  in the terminal and never enters the model's context.

Within one session the hook fires once, so the injected text stays fixed and ordinary
turn-to-turn caching applies.

### Limits of the caching claim

Claude Code decides where cache breakpoints go, and the design notes state that this is not
controllable from the command line. The shared-`COMMON`-prefix saving is therefore a design
intent that depends on where those breakpoints fall. Actual hit rates have not been measured.
The notes also quote cache prices (a cache read costs 0.10× the base input rate) for an
older model, and current rates may differ.
